# Claxis Project TODO

## 1. Крейт `claxis-buffer`

* [x] Piece tree с балансировкой по высоте: вставка и удаление за O(log n).
* [x] Узел и сегмент по 16 байт. Источник текста выводится из записи, а не
      хранится в сегменте.
* [x] Пул узлов фиксированного размера, считается от глубины истории:
      `4 · depth + 8` узлов. Выделяется один раз, аллокаций в горячем пути нет.
* [x] Удаление вырезает сегменты физически, мёртвых сегментов не бывает.
* [x] Записи в двух стеках: `undo` хранит всё, `redo` — только отменённое.
* [x] Арена не теряет записи: блок переполнен — выделяется следующий.
* [x] Тексты отменённых вставок переиспользуются: `Added` обрезается по хвосту.
* [x] Глубина истории — единственная настройка размера, от 1 до 8192 записей.
      Ноль и превышение дают ошибку, не панику.
* [x] Снапшот по исчерпании глубины, **до** записи правки.
* [x] Ни одной паники в библиотечном коде: исчерпание пула — ошибка.
* [x] 54 теста: инварианты дерева, все срезы чтения, все позиции и диапазоны,
      границы арены, эталон на длинных случайных последовательностях.
* [x] Бенчмарки: вставка 115–150 нс независимо от размера документа, частичное
      чтение 4 КБ за 130 нс – 1.6 мкс.
* [x] Хук `SnapshotSink`: буфер отдаёт текст и ничего не знает про диск.
* [x] `set_sink` вешает приёмника на документ.
* [x] `NullSink` по умолчанию: буфер работает и без хранилища.

## 4. Конфиг

### Структура, решена

* [x] Конфиг разнесён по файлам: `config.toml` для общих настроек редактора,
      `edit.toml`, `command.toml`, `files.toml` для состояний.
* [x] Темы и переводы — не файлы настроек, а папки: `theme/<название>.toml`
      и `lang/<код>.toml`. Выбор темы и языка — ключи в `config.toml`.
* [x] Имя файла в ключе не участвует: оно названо самим файлом.
* [x] Внутри `[General]` и режимы в одну скобку, третий уровень разрешён
      только внутри режима.
* [x] Ключи по-английски, без сокращений. Тесты проверяют правила как код.
* [x] Комментарии к ключам переводимы, английский по умолчанию.
* [x] Настройки живут в том крейте, которому принадлежат, а не в буфере.
* [x] `claxis-i18n` — отдельный крейт для перевода, конфиг зависит от него.
      Языки в бинарник не встраиваются, кроме английского.

### Чтение и запись

* [x] Пути: `$XDG_CONFIG_HOME/claxis`, темы в `theme/`, переводы в `lang/`.
* [x] Чтение всех файлов с диска. Отсутствующий файл — не ошибка.
* [x] Генерация при первом запуске: все файлы, все ключи, комментарий к
      каждому. Существующие файлы не трогаются.
* [x] Точечная запись значения: комментарии и порядок ключей сохраняются.
* [x] Ключи, которые код пока не читает, пишутся **закомментированными**: ключ
      есть и понятен, но выключен. Флаг `active` в схеме проверяется тестом
      против списка реально читаемых ключей, врёт — падает.
* [x] Ошибки несут файл, строку, ключ и суть. Строка считается по исходному
      тексту: разбор позицию не отдаёт.
* [x] Загрузка не падает целиком: плохая секция отключается, остальные
      работают. Плохая секция в одном файле не трогает другие.
* [ ] Перенести дефолты в `demo-config`, когда пользователь решит раскладку
      ключей. Отложено по решению пользователя.

### Применение

* [x] Изменение конфига применяется: перечитываем, сверяем, применяем
      разницу. Ничего не дописываем и не дополняем.
* [x] Сломанный конфиг не применяется: остаются старые настройки, проблемы
      возвращаются с файлом, строкой и ключом.
* [x] `snapshots_keep` и `snapshots_persist` применяются на лету, `history_depth`
      честно просит перезапуск: пул узлов задан при создании буфера.
* [x] Последний корректный конфиг хранится в `claxis-store`, редактор идёт на
      него, если текущий сломан. Падает только когда запасного нет.
* [ ] Открывать сломанный конфиг с курсором на строке ошибки и подсвечиванием.
      Нужен `claxis-view`.

### Наблюдение за файлами

* [x] Наблюдение за каталогом конфига через системные уведомления (`notify`).
      Правка снаружи видна открытому редактору, перехватывать своё сохранение
      не нужно.
* [x] Наблюдение не рекурсивное, чужие файлы игнорируются, события копятся до
      устойчивых: иначе читается полузаписанный файл.
* [x] Если подписка не удалась, об этом говорится, а не молчится.
* [x] `Editor::poll_watch` — перечитывает и применяет, если система сообщила
      об изменении.
* [ ] **Цикл должен просыпаться и от файла, и от клавиши.** Сейчас он
      блокируется на вводе в терминале, а `poll_watch` опрашивается между
      нажатиями. Правка извне применится только при следующем нажатии, а если
      пользователь просто смотрит в экран — может не примениться долго.
      «Сразу применяется» в документации сказано зря, поправлено.
* [ ] Как чинить: свести канал наблюдателя и события терминала в один
      источник. На Linux — `poll`/`epoll` на оба дескриптора, либо один общий
      канал, куда наблюдатель шлёт с тегом «это конфиг».
* [ ] Опроса файловой системы нет и не надо: `notify` под Linux это inotify,
      ядро само присылает события. Опросается только канал.

### Локализация конфига

* [ ] Комментарии к ключам приходят из перевода, а не пишутся в коде.
* [ ] Файлы переводов грузятся с диска, шаблон генерируется по каталогу.

* [x] Трейт `Messages` и английский `En` как язык по умолчанию.
* [x] `substitute`: значения подставляются вместо `{имён}` в тексте перевода.
* [x] `ParseError` — что пришло и чего ожидалось, тоже через каталог.
* [ ] Настоящих языков нет, кроме английского. Файлов перевода нет.
* [ ] Чтение `language` из конфига, загрузка TOML, проверка ключей.
* [x] **Отладочная команда `claxis messages`.** Выводит все сообщения всех
      крейтов с настоящими значениями вместо имён в фигурных скобках:
      переводчик видит, как сообщение выглядит на самом деле. Работает без
      терминала, команды разбираются до его открытия.
* [x] `claxis help`, разбор аргументов. Неизвестный аргумент не ошибка:
      это может быть путь к файлу.
* [ ] **Тест вывода CLI в терминале.** Запускает команду в псевдотерминале,
      снимает что видно на экране и сверяет с эталоном («картинки» терминала).
      Ловит то, что обычный тест не поймает: битые escape-последовательности,
      неправильный вывод цвета, съехавшая разметка.
* [x] Тест проверяет, что в вывод попадает каждый крейт и что незаполненных
      имён в фигурных скобках не остаётся.
* [x] Каталоги сообщений у всех крейтов, включая `claxis-i18n` и
      `claxis-config`, которые раньше выдавали текст напрямую через `Display`.
* [x] Комментарии конфига переводимы: ключ — английская фраза, каталог ищет
      её как есть. Проверено тестом с русским каталогом.
* [x] Справка CLI переводима, а не зашита в коде.
* [ ] Настоящих языков нет: английский зашит, файлы переводов не читаются.
* [ ] Крейты при создании должны сразу брать каталог, а не дописывать
       задним числом: проверено только аудитом, автопроверки нет.

## 6. Крейты и их настройки

Настройки живут в том крейте, которому принадлежат, а не в буфере.

* [x] `claxis-buffer` — только `history_depth`.
* [x] `claxis-store` — `keep`, `persist`. Перенесено из буфера.
* [x] `claxis-input` — `tap_hold_ms`. Крейт создан заранее, чтобы настройка
      не потерялась и не лежала не в том крейте.
* [x] `claxis-text` — общее форматирование в одном месте: `substitute` и
      `group_digits`. Правило: правится здесь, а не в каждом крейте.
* [x] `claxis-term` — kitty keyboard protocol, raw mode, размер, события.
      Свои типы событий, не crossterm-овские. 10 тестов.
* [x] `main.rs` — тонкий бинарь: открывает терминал, читает события, печатает,
      выходит по Ctrl+Q. Отказ без протокола с внятным сообщением.
* [x] `claxis-config` — см. раздел 4.
* [ ] `claxis-theme` — список тем в папке и проверка имени темы, на которую
      указывает `config.toml`. Согласовано, содержания пока нет.
* [ ] `claxis-input` — механика нажатия и удержания, раскладки, модификаторы.
      Крейт создан, кода нет.
* [ ] `claxis-commands`, `claxis-view`, `claxis-i18n` (сделаны основы),
      `claxis-core`, `claxis-search`, `claxis-files`, `claxis-modes`,
      `claxis-plugin` — создаются по мере появления содержания.
