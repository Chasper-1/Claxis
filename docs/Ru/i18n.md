# Локализация (i18n)

> **О чём документ:** этот документ описывает систему локализации интерфейса — формат файлов переводов, что переводится и что нет, подключение пользовательских переводов и генерацию шаблона перевода. Документ фиксирует уже принятые проектные решения.

---

## Принципы

1. **Все строки интерфейса переводимы.** Ни одной зашитой в код строки пользовательского интерфейса.
2. **Формат — TOML-файлы**, по одному на язык.
3. **Ключи — английские фразы**, они же используются в коде: в коде всегда пишется английская строка, а перевод подставляется на этапе отображения.

## Что не переводится

**Названия команд (`std::...`) не переводятся** — они часть внутренней логики редактора, а не строки интерфейса (см. [`command-system.md`](command-system.md)).

## Подключение перевода

Пользователь может создать или подключить перевод **любого языка**: достаточно указать путь к TOML-файлу перевода в конфигурации ([`config.md`](config.md)). Отсутствующие ключи откатываются к английским фразам-ключам.

## Генерация шаблона

CLI-команда генерирует **пустой файл перевода со всеми ключами**, чтобы переводчику оставалось только заполнить значения:

```sh
my-editor i18n new --lang ru
```

## Пример файла перевода

```toml
# Файл перевода: keys — английские фразы из кода, values — перевод.
"Open file" = "Открыть файл"
"Save file" = "Сохранить файл"
"Unsaved changes" = "Есть несохранённые изменения"
# Названия команд не переводятся и здесь не фигурируют:
# std::file::open остаётся std::file::open.
```
