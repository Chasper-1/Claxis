# Парсинг-движок

Долгосрочное видение, не план работ. Не блокирует MVP и не входит ни в один его этап.

## Три слоя

Цель — универсальный нативный парсинг-движок, а не только подсветка: полное конфигурируемое построение дерева разбора любого языка и LSP-фичи поверх дерева.

| Слой | Ответственность |
|---|---|
| Движок грамматик | Язык описывается конфигом, SIMD ускоряет сканирование токенов |
| Семантический слой | Анализ поверх дерева на встраиваемом языке |
| Потребители | Всё, что читает дерево: подсветка, outline, фолдинг, go-to-definition |

Отличие от tree-sitter: tree-sitter решает только слой грамматик и только для языков, чьи грамматики записаны на его диалекте. Упакованного решения «конфиг, дерево, семантика, LSP» у него нет.

## Error recovery

Ключевая проблема: код в процессе набора всегда невалиден. Пользователь печатает посреди выражения — парсер обязан работать с недописанным кодом.

Нужно не падать на невалидном коде, не перечитывать весь файл после каждой правки, перестраивать только затронутую часть дерева.

Выбор формализма грамматик открыт: PEG проще конфигурировать, но слабее восстанавливается после ошибок; GLR мощнее и толерантнее к невалидному коду, но сложнее.

## SIMD

Классификация байтов через битовые маски, прецедент — memchr. SIMD закрывает токенизацию, это лёгкие двадцать процентов работы. Грамматика с error recovery остаётся скалярной и является самой сложной частью движка.

portable SIMD в Rust пока nightly-only, поэтому стабильный путь: интринсики `std::arch`, runtime-детекция возможностей CPU, стиль как у memchr.

## Эволюция в DSL

Стартовая точка — JSON-грамматики, затем собственный DSL, затем транслятор DSL в Rust в WASM.

Через Rust потому, что бэкенд и оптимизации достаются бесплатно от экосистемы, а распространение артефактов идёт через `.wasm`. Корректность обеспечивается по конструкции: DSL спроектирован так, что невалидный Rust невыразим, а все ошибки ловятся на уровне DSL с понятными сообщениями.

| Компонент | Где живёт |
|---|---|
| wasmtime-рантайм | Внутри редактора |
| Компилятор DSL в WASM | В тулчейне автора плагина |

Редактор содержит только рантайм, автор собирает артефакт у себя и публикует готовый.

Эргономика DSL: уровень языка как у Markdown, типовая грамматика двести-триста строк, максимальный размер файла до тысячи строк, API декларативный через константы, документация генерируется из тех же метаданных, что описывают API.

Перед проектированием изучаются pest, LALRPOP и tree-sitter с фокусом на их больных местах: качество диагностики и выразительность.
