## Три слоя

Цель — универсальный нативный парсинг-движок, а не только подсветка: полное конфигурируемое построение дерева разбора любого языка и LSP-фичи поверх дерева.

| Слой | Ответственность |
|---|---|
| Движок грамматик | Язык описывается конфигом, SIMD ускоряет сканирование токенов |
| Семантический слой | Анализ поверх дерева на встраиваемом языке |
| Потребители | Всё, что читает дерево: подсветка, outline, фолдинг, go-to-definition |

Отличие от tree-sitter: tree-sitter решает только слой грамматик и только для языков, чьи грамматики записаны на его диалекте. Упакованного решения «конфиг → дерево → семантика → LSP» у него нет.

## Error recovery

Ключевая проблема: **код в процессе набора всегда невалиден**. Пользователь печатает посреди выражения — парсер обязан работать с недописанным кодом.

Требования:

- не падать на невалидном коде;
- не перечитывать весь файл после каждой правки;
- перестраивать только затронутую часть дерева — частичный репарс от точки правки.

Выбор формализма грамматик — **открытый вопрос**:

| Формализм | Плюсы | Минусы |
|---|---|---|
| PEG | Проще конфигурировать | Слабее восстановление после ошибок |
| GLR | Мощнее, толерантнее к невалидному коду | Сложнее |

## SIMD

Механизм — классификация байтов через битовые маски. Прецедент — [`memchr`](https://github.com/BurntSushi/memchr).

SIMD закрывает токенизацию — это лёгкие ~20% работы. Грамматика с error recovery остаётся скалярной и является самой сложной частью движка.

portable SIMD (`std::simd`) в Rust пока **nightly-only**, поэтому стабильный путь зафиксирован такой:

- интринсики `std::arch` (`_mm256_*` для x86, NEON для ARM);
- runtime-детекция возможностей CPU;
- стиль реализации — как у `memchr`.

## Эволюция в DSL

1. JSON-грамматики — стартовая точка.
2. Собственный DSL поверх них.
3. Транслятор **DSL → Rust → WASM**.

Почему через Rust: бэкенд и оптимизации достаются бесплатно от экосистемы, а распространение артефактов идёт через `.wasm` (см. [plugins.md](plugins.md)). Корректность обеспечивается по конструкции: DSL спроектирован так, что невалидный Rust невыразим, а все ошибки ловятся на уровне DSL с понятными сообщениями.

### Сборка и рантайм

| Компонент | Где живёт |
|---|---|
| wasmtime-рантайм | Внутри редактора |
| Компилятор DSL → WASM | В тулчейне автора плагина |

Редактор содержит только рантайм; автор собирает `.wasm` у себя и публикует готовый артефакт.

### Эргономика DSL

| Цель | Значение |
|---|---|
| Уровень языка | Сложность Markdown |
| Типовая грамматика | ≈ 200–300 строк DSL |
| Максимальный размер файла | до 500–1000 строк |
| API | Декларативный, через константы |
| Документация | Генерируется из тех же метаданных, что описывают API |

Перед проектированием DSL изучаются **pest**, **LALRPOP**, **tree-sitter** — фокус на их больных местах: качество диагностики и выразительность.
