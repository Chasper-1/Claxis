## Событийный цикл

Один цикл на всё приложение:

1. **Ввод** — crossterm отдаёт событие клавиши.
2. **Трансляция** — привязка ищется по цепочке контекстов: режим → состояние → глобально. Результат — команда `std::edit::move::up`.
3. **Выполнение** — команда применяется к буферу, курсорам, файлам.
4. **Инкрементальный рендер** — перерисовываются только изменившиеся ячейки.

## Интерфейс

### Вкладки

**Вертикальные вкладки** — осознанный выбор удобства против привычности: горизонтальные вкладки съедают высоту строк кода.

Требования к рендеру:

- длинные имена обрезаются с сохранением различимой уникальной части;
- при переполнении панели список вкладок прокручивается;
- при одной вкладке панель схлопывается и не занимает место.

### Разделение экрана

Сплитов нет. Максимум — два файла одновременно. Полноценная система сплитов не строится.

### Статус-бар

Вся служебная информация — в одной строке: имя файла, активный режим, позиция курсора. Состав виджетов настраивается, строка ввода появляется на время работы и не висит на экране постоянно.

### Цвета режимов

Активный режим выделяется цветом в статус-баре. Набор цветов задаётся темой, подписи режимов — конфигом.

## Файлы и сессии

- Открытие папки запускает встроенный файловый менеджер.
- Сессия привязана к директории: набор открытых файлов, курсоры и состояние сохраняются отдельно для каждой папки.
- Одиночный файл открывается как отдельная сессия; если сессия его папки существует, предлагается перейти в неё.

## Внешние LSP

Поддержка Language Server — через **публичный API** редактора. В ядро LSP жёсткой зависимостью не входит.

---

## Shell-команды

Выполняются в директории открытого файла или проекта. Эмуляция терминала не делается.

---

## Мышь

Мышь — **второстепенный ввод**: позиционирование курсора, прокрутка, средняя кнопка. Все действия доступны без мыши.

---

## Безопасность данных

| Тип данных | Формат | Стратегия записи |
|---|---|---|
| Документы | Обычный текст | **Атомарная запись**: временный файл → `rename` |
| Служебные файлы | Бинарный аппендабельный | Дозапись |

Атомарная запись исключает потерю документа при сбое питания в момент сохранения. Подробности — [buffer-and-cursors.md](buffer-and-cursors.md).

---

## Производительность

- **Rope-буфер** — вставка и удаление за O(log n), копирование больших документов бесплатно.
- **Инкрементальный рендер** — обновляются только изменившиеся ячейки терминала.
