# Архитектура редактора

> **О документе:** фиксирует принятые архитектурные решения TUI-редактора: платформу, состав модулей крейта, событийный цикл, устройство интерфейса, работу с файлами и сессиями, безопасность данных и подход к производительности. Документ описывает *что* решено; детали отдельных подсистем вынесены в специализированные документы (см. ссылки по тексту).
>
> См. также: [philosophy.md](philosophy.md) — философия проекта.

---

## 1. Платформа

| Решение | Значение |
|---|---|
| Формат | **TUI-only** |
| Язык | Rust |
| Терминальный бэкенд | ratatui + crossterm (кандидаты) |

**GUI не делается никогда.** Это осознанное стратегическое решение: в GUI-сегменте конкурировать с Zed бессмысленно. Ниша редактора — терминал, где он может быть лучшим.

## 2. Модули крейта

На старте — **один крейт с модулями**. При разрастании проект переходит на workspace-структуру (решение о моменте перехода — по факту роста, заранее не фиксируется).

| Модуль | Ответственность | Детали |
|---|---|---|
| `buffer` | Rope-буфер документа | [buffer-and-cursors.md](buffer-and-cursors.md) |
| `modes` | Машина состояний (4 глобальных состояния + режимы) | [modes.md](modes.md) |
| `commands` | Реестр и исполнение команд | [command-system.md](command-system.md) |
| `config` | Конфигурация (TOML) | [config.md](config.md) |
| `ui` | Рендер, вкладки, командный режим | — |
| `i18n` | Локализация интерфейса | — |
| `tutorial` | Встроенный обучающий курс | — |
| `plugins` | Макросы + Rhai-плагины (асинхронно) | [plugins.md](plugins.md) |
| `search` | Поиск и замена | — |

Зависимости между модулями направленные: `ui`, `commands`, `search` работают поверх `buffer`/`cursor`; `config` и `i18n` — вспомогательные слои без обратных связей.

## 3. Событийный цикл

Один цикл на всё приложение:

```mermaid
flowchart LR
    A[Ввод: событие клавиши] --> B[Трансляция в команду]
    B --> C[Выполнение команды]
    C --> D[Инкрементальный рендер]
    D --> A
```

1. **Ввод** — crossterm отдаёт событие клавиши.
2. **Трансляция** — клавиша ищется в привязках по цепочке контекстов: **режим → состояние → глобально**. Результат — команда вида `std::edit::move::up`.
3. **Выполнение** — команда применяется к состоянию (буферу, курсорам, файлам).
4. **Инкрементальный рендер** — перерисовываются **только изменённые ячейки** терминала, а не весь экран.

## 4. Интерфейс

### Вкладки

Используются **вертикальные вкладки** — осознанный выбор удобства против привычности (горизонтальные вкладки съедают высоту строк кода).

TUI-нюансы, которые обязан учитывать рендер:

- **Обрезка длинных имён**: имя файла обрезается так, чтобы оставалась различимая уникальная часть.
- **Много вкладок**: при переполнении панели — прокрутка списка вкладок.
- **Ширина панели**: при одной открытой вкладке панель схлопывается и не должна жрать полезное пространство.

### Разделение экрана

Сплитов нет. Максимум разделения экрана — **два файла одновременно**. Полноценная система сплитов сознательно не строится.

### Минимализм

Вся служебная информация (имя файла, режим, позиция курсора) — **только в однострочном баре** внизу. Никаких постоянно отображаемых пустых командных строк, статусных панелей и прочих элементов, съедающих полезное пространство. Экран принадлежит тексту (см. philosophy.md).

## 5. Состояния и режимы

Четыре глобальных состояния (Edit, File, Search, Command) с режимами внутри каждого. Переключение между состояниями — через командный режим (Alt). Хоткеи — через режим Hotkey (Ctrl). Подробности — в [modes.md](modes.md).

| Состояние | Назначение |
|---|---|
| **Edit** | Ввод текста, навигация, выделение, удаление (по умолчанию) |
| **File** | Создание/открытие/перемещение/сохранение файлов, Git |
| **Search** | Поиск и замена (текст, regex, фильтры) |
| **Command** | Алиасы Vim-стиля (Alt зажат, выполнение при отпускании) |

Логика курсора универсальна внутри каждого состояния; поддерживаются повторения и режимы (например, замена символа). Подробности — в [modes.md](modes.md).

## 6. Файлы и сессии

- **Открытие папки** = запуск встроенного файлового менеджера со всеми файлами папки.
- **Сессии привязаны к запущенной папке**: набор открытых вкладок, курсоров и состояния сохраняется для конкретной директории.
- **Одиночный файл** открывается как отдельная сессия; при этом пользователю **предлагается перейти к сессии папки**, если она существует.

## 7. Внешние LSP

Поддержка внешних Language Server — через **публичный API** редактора. LSP не встраивается в ядро как жёсткая зависимость.

## 8. Shell-команды

Shell-команды выполняются **в директории открытого файла/проекта**. Полноценная эмуляция терминала **не делается** — редактор не превращается в tmux.

## 9. Мышь

Мышь поддерживается как **второстепенный ввод** (клик для позиционирования курсора, прокрутка). Основной сценарий — клавиатура; все действия доступны без мыши.

## 10. Безопасность данных

Данные разделяются на два класса с разной стратегией записи:

| Тип данных | Формат | Стратегия записи |
|---|---|---|
| Документы пользователя | Обычный текст | **Атомарная запись**: запись во временный файл → `rename` |
| Внутренние служебные файлы (состояние, история) | Бинарный аппендабельный формат | Дозапись; детали — [buffer-and-cursors.md](buffer-and-cursors.md) |

Атомарная запись исключает потерю документа при сбое питания или падении процесса в момент сохранения.

## 11. Производительность

Два столпа производительности заложены в архитектуру с самого начала:

- **Rope-буфер** (`buffer`) — операции вставки/удаления O(log n), копирование больших документов бесплатно;
- **Инкрементальный рендер** (`ui`) — обновляются только изменённые ячейки терминала.

Критерий: **задержка ввода замеряется тестами** — метрика является частью CI-гейтов, а не субъективным ощущением.
