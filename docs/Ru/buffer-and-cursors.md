## Rope-буфер

Буфер текста реализуется структурой **rope** (канат). Кандидат — крейт [`ropey`](https://crates.io/crates/ropey).

Почему rope, а не `String`:

| Операция | `String` | Rope |
|---|---|---|
| Вставка в середину большого файла | O(n) — сдвиг всего хвоста | O(log n) |
| Удаление в любом месте | O(n) | O(log n) |
| Чтение по смещению | O(1) | O(log n) |
| Работа с большими файлами | деградирует | стабильна |

Решение зафиксировано: rope с самого начала. Переделка буфера после того, как на нём построены все операции, — самый дорогой вид рефакторинга.

## Структура курсора

Курсор — это пара точек:

```rust
struct Cursor {
    anchor: Position, // якорь — фиксированный конец
    head: Position,   // голова — активный конец
}
```

| Состояние | Значение |
|---|---|
| `anchor == head` | **точка** — обычный курсор без выделения |
| `anchor != head` | **выделение** между якорем и головой |

Выделение получается **бесплатно из модели курсора**: не нужен отдельный механизм «режима выделения» на уровне данных — достаточно двух позиций вместо одной.

## Undo/redo: гибридная модель

История правок строится по гибридной модели группировки событий:

| Механизм | Правило |
|---|---|
| **Пауза ввода** | Непрерывный набор склеивается в одну запись; пауза больше таймаута (мс) открывает новую запись |
| **Границы слов** | Пробел — разделитель слов: слово удаляется/вставляется как одна единица undo |
| **Тип события** | Вставка — отдельный тип события со своими правилами группировки |

Принципы:

- **Правила настраиваемые** поверх базовой модели: таймаут, символы-разделители, типы событий задаются конфигурацией.
- **Заложено место под сохранение истории между запусками** — восстановление сессии с историей. Это будущее расширение, **не MVP**, но формат записей истории проектируется с учётом сериализации.

## Кодировки и переводы строк

### Кодировки

При открытии файла кодировка **определяется автоматически**:

| Поддерживаемые кодировки |
|---|
| UTF-8 |
| UTF-16 |
| Latin-1 |

Файл **сохраняется в исходной кодировке**: открыли Latin-1 — сохранился Latin-1. Конвертация «на лету» при сохранении не выполняется.

### Переводы строк и BOM

Поддерживаются все три варианта конца строки: `LF`, `CRLF`, `CR`. BOM распознаётся при чтении и воспроизводится при записи.

## Сохранение и безопасность данных

Разделение на два типа файлов — принципиальное решение:

### Документы пользователя — всегда обычный текст

Документы никогда не хранятся ни в чём, кроме обычного текста. Причины:

- `git diff` читает изменения напрямую;
- файл можно посмотреть через `cat`, открыть любым другим редактором;
- полная совместимость с экосистемой инструментов.

Никаких встроенных метаданных, сжатия или собственного формата внутри документа пользователя.

### Атомарная запись

Сохранение выполняется атомарно: запись во временный файл → `rename` поверх целевого. Падение питания в середине записи не оставляет наполовину испорченный документ — либо старая версия, либо новая.

### Служебные файлы — бинарный аппендабельный формат

Внутренние служебные данные (backup, восстановление после падения) хранятся в **бинарном аппендабельном формате**:

- быстрое чтение и запись;
- дописывание новых данных **без перезаписи всего файла** — критично для журнала восстановления.
