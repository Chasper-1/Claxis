## Rope-буфер

Текст хранится в структуре **rope**. Кандидат — крейт [`ropey`](https://crates.io/crates/ropey).

| Операция | `String` | Rope |
|---|---|---|
| Вставка в середину большого файла | O(n) — сдвиг хвоста | O(log n) |
| Удаление | O(n) | O(log n) |
| Чтение по смещению | O(1) | O(log n) |
| Большие файлы | деградация | стабильна |

Решение зафиксировано на старте: переделка буфера после того, как на нём построены все операции, — самый дорогой рефакторинг в проекте.

## Курсор

Курсор — пара точек:

```rust
struct Cursor {
    anchor: Position, // якорь — неподвижный конец
    head: Position,   // голова — активный конец
}
```

| Соотношение | Значение |
|---|---|
| `anchor == head` | Точка — обычный курсор |
| `anchor != head` | Выделение между якорем и головой |

Выделение получается бесплатно из модели курсора: отдельный механизм выделения на уровне данных не нужен — хватает двух позиций вместо одной.

## Undo/redo

История группируется по событиям:

| Механизм | Правило |
|---|---|
| Пауза ввода | Непрерывный набор склеивается в одну запись; пауза длиннее таймаута открывает новую |
| Границы слов | Пробел — разделитель: слово вставляется и удаляется как одна единица |
| Тип события | Вставка — отдельный тип со своими правилами группировки |

Правила настраиваются поверх базовой модели: таймаут, символы-разделители и типы событий задаются конфигом. Формат записей проектируется с учётом сериализации, чтобы историю можно было восстановить между запусками — это развитие, не MVP.

## Кодировки и переводы строк

| Кодировка | Поддержка |
|---|---|
| UTF-8 | да |
| UTF-16 | да |
| Latin-1 | да |

Кодировка определяется при открытии, файл сохраняется **в исходной кодировке**: открыли Latin-1 — сохранился Latin-1. Конвертация при сохранении не выполняется.

Переводы строк: `LF`, `CRLF`, `CR`. BOM распознаётся при чтении и воспроизводится при записи.

## Сохранение

### Документы — обычный текст

Документы хранятся только в виде обычного текста:

- `git diff` читает изменения напрямую;
- файл виден через `cat` и открывается любым другим редактором;
- полная совместимость с экосистемой инструментов.

Никаких метаданных, сжатия или собственного формата внутри документа.

### Атомарная запись

Сохранение идёт через временный файл с последующим `rename`. Падение питания в середине записи не оставляет наполовину испорченный документ: либо старая версия, либо новая.

### Служебные файлы — бинарный аппендабельный формат

Внутренние данные (backup, последняя рабочая версия конфига, журнал восстановления) хранятся в формате, который позволяет дописывать без перезаписи всего файла.
