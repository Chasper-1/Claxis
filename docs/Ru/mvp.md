# MVP и roadmap

## MVP

**Цель:** просто рабочий редактор без плагинов, подсветки и прочего. Запускается в терминале с kitty keyboard protocol, открывает файл, позволяет писать, навигировать, выделять, выполнять команды, менять привязки и сохранять без потери данных.

| # | Компонент | Что входит |
|---|---|---|
| 1 | Протокол терминала | Запрос флагов, отказ без протокола, восстановление при выходе |
| 2 | Буфер | Piece tree, позиции, курсор, выделение, кодировки, `LF`/`CRLF`/`CR`, BOM |
| 3 | Undo | Группировка по паузе ввода и границам слов, redo |
| 4 | Слой ввода | Модификаторы, переназначение клавиш, лидер, отмена |
| 5 | Раскладки | Клавиша как позиция, эталонная раскладка, таблицы раскладок, определение активной |
| 6 | Команды | Реестр `std::…`, автодополнение, алиасы, хоткеи, повторы, три уровня, конфликты |
| 7 | Конфиг | Схема, загрузка, валидация, дубликаты привязок, точечная запись |
| 8 | Тема | Цвета состояний и режимов |
| 9 | Рендер | Вьюпорт, инкрементальный дифф, статус-бар, командная строка, вкладки, приветственный экран |
| 10 | Локализация | Каталог, откат к ключу, генератор шаблона |
| 11 | Файлы | Открытие, атомарное сохранение |

**Критерий готовности.** В терминале с протоколом: редактор запускается в состоянии `command`, открывает файл, под модификатором печатается текст, без него работают навигация и команды, выделение расширяется, автодополнение подсказывает команды по уровням, числовой префикс даёт повтор, привязка меняется в конфиге, дубликат между уровнями даёт внятную ошибку с названием клавиши и уровней, раскладки определяются по вводу и настраиваются, файл сохраняется в исходной кодировке с исходными переводами строк, документ не теряется при обрыве записи. В терминале без протокола — внятное сообщение и предложение выключить соответствующую логику работы модификаторов.

Подсветки синтаксиса, поиска и LSP в MVP нет. Писать код можно и без подсветки, это дополняющая возможность, а не условие работоспособности.

## Порядок сборки

Крейты появляются в порядке зависимостей, бинарь — тонкая оболочка с первого шага, иначе до конца нечего запустить.

| Шаг | Что появляется | Работающий результат |
|---|---|---|
| 1 | `core` | Буфер двигается, тест проходит, экрана нет |
| 2 | `term` и тонкий бинарь | Пустой экран, реакция на нажатия, отказ без протокола |
| 3 | `config` | Конфиг грузится, ошибки валидации видны |
| 4 | `input` | Модификаторы, раскладки разрешаются |
| 5 | `commands` | Команды, алиасы и хоткеи выполняются, автодополнение подсказывает |
| 6 | `theme` | Цвета состояний и режимов |
| 7 | `view` | Текст на экране, скролл, статус-бар, командная строка с подсказками |
| 8 | undo в `core` | Отмена и повтор |
| 9 | файлы в бинаре | Открытие и атомарное сохранение |
| 10 | вкладки и приветствие в `view` | Вертикальные вкладки, первый запуск |
| 11 | `i18n` | Перевод интерфейса |

После шага 7 редактор уже пригоден для правки текста, шаги 8–11 доводят его до критерия готовности.

После каждого шага: `cargo build`, `cargo test`, `cargo clippy -- -D warnings`. Крейт без теста не готов.

## Этап 2 — Локализация

**Цель:** интерфейс полностью переводим.

Каталог переводов с откатом к английскому ключу, CLI-команда для генерации шаблона, подписи режимов в конфиге.

**Критерий готовности:** при `language = "ru"` все строки интерфейса переведены, генератор шаблона создаёт файл со всеми ключами для переводчика.

## Этап 3 — Движок обучения

**Цель:** встроенный мини-курс, который к концу оставляет пользователя с персонализированным конфигом.

Движок обучения со встроенными уроками и загрузкой внешних TOML. Уроки из реальных действий, а не стены текста. Курс пишет конфиг: при изучении команды предлагает назначить её алиасом или хоткеем. Автозапуск при первом старте, отключение конфигом или флагом. Урок может предложить записать последовательность действий как макрос.

**Критерий готовности:** новичок проходит курс от старта до конца, каждое изученное действие выполняет руками, назначенные привязки сохранены в конфиге и работают после перезапуска.

## Этап 4 — Файлы, Git, история

**Цель:** повседневный рабочий цикл разработчика без выхода из редактора.

Файловый менеджер, сессии по директориям, Git-интеграция в состоянии `files`, режим `replace_char`, история команд с навигацией `↑` и `↓`.

**Критерий готовности:** состояние `files` открывает и сохраняет файлы, базовые Git-операции выполняются из него, сессия восстанавливается после перезапуска в той же директории, замена символа работает как отдельный режим, предыдущие команды вызываются из истории.

## Этап 5 — Орфография и подсказки слов

**Цель:** умная текстовая поддержка без тяжёлых зависимостей.

Проверка орфографии по hunspell-словарям, подсказки слов по Tab из частотного словаря. Грамматика уровня LanguageTool — отдельный многолетний проект и не часть редактора.

**Критерий готовности:** опечатки подсвечиваются по словарю выбранного языка, Tab достраивает слово по частотному словарю, обе функции отключаются конфигом.

## Этап 6 — Языки и LSP

**Цель:** подсветка и понимание кода.

Грамматики, подсветка, инкрементальный репарс. Публичный API редактора, транспорт, управление процессами LSP. Ключи автодополнения в конфиге начинают работать.

**Критерий готовности:** подсветка появляется по мере набора, большой файл не перечитывается целиком при правке в первой строке, LSP-сервер подключается, отдаёт диагностику и определения, не блокируя ввод.

## Долгосрочное видение

За пределами этапов лежит универсальный парсинг-движок: в общем виде должен скомбинировать в себе все важные инструменты для работы с кодом. LSP-сервер, подсветка синтаксиса. Так же иметь возможность написать на этой основе плагины.
