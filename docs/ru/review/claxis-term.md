# Ревью: `claxis-term`

Дата ревью: 2026-11-12 (вторая версия).
Состояние крейта: 846 строк, 22 теста, все проходят.

## 1. Назначение и границы

Крейт — терминал как устройство: протокол, raw mode, чтение событий.

| Что есть | Что не входит в крейт |
| --- | --- |
| Включение и выключение kitty keyboard protocol | Смысл клавиш: это `claxis-input` |
| Raw mode с гарантированным выходом | Раскладки и привязки |
| Свои типы событий: нажатие, отпускание, повтор, вставка, мышь | Политика: что нажатие значит |
| Размер терминала | Отрисовка |

Зависимости: `claxis-text`, `crossterm`. Свои типы событий — сознательное
решение: у `crossterm` нет отдельного типа отпускания, а модель ввода без
него не работает.

## 4. Что сделано хорошо

- **Отказ, а не деградация.** Без kitty keyboard protocol «отпустил Alt» не
  отличить от нового нажатия, поэтому редактор прямо говорит об этом и
  выходит.
- **Порядок при запуске выбран правильно.** Сначала raw mode, потом проверка
  протокола: в обычном режиме ввод построчно буферизован, и ответ терминала
  не прочитался бы до конца ожидания — поддержка выглядела бы отсутствующей
  там, где она есть.
- **Ответ терминала разбирается устойчиво.** Ответ может прийти после мусора,
  разорванным на части, с битым UTF-8, или несколькими ответами подряд — все
  случаи разобраны и покрыты тестами.
- **Ноль в ответе считается поддержкой.** Терминал с полной поддержкой
  отвечает `0`, и редактор отказался бы работать впустую.
- **Автоповтор — отдельное событие.** Повтор не начинает новое нажатие, он
  продолжает старое: иначе время удержания перезаписывалось бы, а счётчик
  нажатий считал бы удержание десятками нажатий.
- **Вставка и мышь не теряются.** Молча пропавший текст хуже отшибка.
- **Выход гарантирован.** `RawMode` — guard: при панике терминал
  возвращается в исходное состояние, и об этом ещё и печатается, потому что
  сломанный терминал человек ищет полминуты после выхода из редактора.

## 5. Находки

| # | Серьёзность | Где | Что не так |
| --- | --- | --- | --- |
| 1 | важно | `src/protocol.rs:76` | Проверка поддержки может висеть бесконечно. `stdin.read()` на терминале блокируется до первого байта, а срок в 100 мс проверяется только между чтениями. На терминале без протокола, если человек ничего не печатает, `supports()` не вернётся никогда — ровно тот случай, ради которого срок и поставлен: код сам обещает «ждать вечно нельзя» |
| 2 | важно | `src/protocol.rs:82` | Введённые за эти 100 мс символы теряются: прочитанное из stdin отбрасывается, кроме ответа. Человек, который начал печатать сразу после запуска, потеряет первые буквы и не поймёт почему |
| 3 | важно | `src/lib.rs:87`, `src/raw.rs:40` | Текст при аварийном выходе печатается английским каталогом `En` и идёт в `stderr`, минуя каталог пользователя. При выбранном другом языке сообщение о сломанном терминале останется английским. И это же происходит во время паники, когда `stderr` может быть в непригодном состоянии |
| 4 | важно | `src/reader.rs:15` | Чтение только блокирующее: `crossterm::event::read()`. Циклу редактора нужен опрос с таймаутом — иначе снапшоты по времени не тикают без событий. Метода «прочитать, если что-то есть» у крейта нет |
| 5 | мелочь | `src/raw.rs:29` | `leave(self)` съедает guard, и `Drop` после этого отключает raw mode второй раз. Обычно безвредно, но при сбое первого отключения второй напечатает ошибку, которой на самом деле нет |
| 6 | мелочь | `src/event.rs:83` | Поле `super_` — имя с подчёркиванием, что `AGENTS.md` запрещает |
| 7 | мелочь | `src/event.rs:116` | `KeyCode` описывает клавиши именами, а не позициями. Модель «клавиша как позиция» из `docs/ru/modes.md` ещё не сделана, и когда её будут делать, текущий `KeyCode` придётся расширять |
| 8 | мелочь | `src/event.rs:46` | В событии мыши нет модификаторов: выделение с `Shift` не отличить от обычного. `crossterm` их передаёт |

## 6. Нарушения правил из `AGENTS.md`

| Правило | Как в этом крейте |
| --- | --- |
| `unwrap`/`expect`/`allow`, имена с `_` | Имена с `_`: `super_` (находка 6) |
| Файл больше 1000 строк | Нет: максимум 236 |
| Паника вместо ошибки | Паник нет; ошибка протокола — `TermError` с текстом |
| Ошибка доходит до пользователя текстом | Да: каталог есть, примеры в `samples()`; но аварийные сообщения идут мимо каталога пользователя (находка 3) |
| Молчание только с комментарием | Соблюдено: при отказе наблюдения и при сбое выхода сообщение печатается |
| Тест рядом с кодом | Да |
| Каталог у крейта с первого года | Есть, `src/messages.rs` |
| Новые зависимости только при необходимости | `crossterm` — для ввода и raw mode |
| `unsafe` | Не используется |
| Крейты напрямую | Только `claxis-text` |

Одно формальное нарушение — `super_`.

## 7. Тесты

22 теста, все проходят.

| Что покрыто | Чего не хватает |
| --- | --- |
| Последовательности протокола: запрос, включение, выключение | — |
| Ответ терминала: ноль, активные флаги, все значения флагов, тишина, обрыв, не число | — |
| Ответ после мусора, разорванный ответ, несколько ответов, битый UTF-8 | — |
| События: нажатие, отпускание, повтор, модификаторы, изменение размера, фокус, вставка, мышь | — |
| Служебные клавиши пропускаются, движение мыши пропускается | — |
| Raw mode: вход и выход | Сам raw mode не проверяется: тест требует настоящего терминала, его нет |
| Размер терминала | Проверяется только структура |

Тесты покрывают разбор протокола и конвертацию событий полностью — это самая
хрупкая часть крейта, и она проверена хорошо. Не покрыто то, что требует
живого терминала: сам raw mode, поведение при зависании опроса (находка 1) и
потерянный ввод (находка 2).

## 8. Долг и предложения

По порядку:

1. **Сделать опрос поддержки с настоящим таймаутом** (находка 1): перевести
   stdin в неблокирующий режим на время запроса или читать через `poll`.
   Сейчас обещание «100 мс» не выполняется, и на терминале без протокола
   редактор может зависнуть вместо внятного отказа.
2. **Не терять введённое во время опроса** (находка 2): байты до ответа
   нужно вернуть в буфер ввода, а не выбросить.
3. **Дать циклу читать с таймаутом** (находка 4): нужен метод «прочитать
   событие, если оно уже есть», иначе таймеры в цикле не тикают.
4. **Печатать аварийные сообщения каталогом пользователя** (находка 3) — это
   правка в корневом крейте: каталог должен дойти до крейта.
5. **Переименовать `super_`** (находка 6) и убрать двойное отключение raw mode
   (находка 5).

Правка 1 — самая важная: она превращает зависание в внятный отказ, который
в проекте уже обещан пользователю.
