# Ревью: `claxis-input`

Дата ревью: 2026-11-12 (вторая версия).
Состояние крейта: 357 строк, 18 тестов, все проходят.

## 1. Назначение и границы

Крейт задуман как слой ввода: клавиши как позиции, раскладки, модификаторы,
составление, лидер, отмена.

| Что есть | Что не входит в крейт |
| --- | --- |
| Окна удержания для клавиш с двумя значениями | События терминала: это `claxis-term` |
| Решение «тап или удержание» по времени | Раскладки и сопоставление позиций — не сделано |
| Настройки по умолчанию (`alt`, `ctrl` по 200 мс) | Привязки команд и модификаторов — не сделано |

Зависимостей нет вообще. Границы соблюдены.

## 3. Публичный API

| Элемент | Оценка |
| --- | --- |
| `Hold` — окна по именам клавиш | Уместен |
| `HoldKey` | Уместен |
| `Resolved` — `Waiting`, `Tapped`, `Held` | Уместен, но `Waiting` никогда не выдаётся — находка 3 |
| `Tap` — `Tap`, `Held` | Мёртвый тип: дублирует половину `Resolved` — находка 2 |
| `resolve(hold, key, held_ms)` | Уместен: состояние нажатия держит вызывающий |
| `DEFAULT_HOLD` | Уместен; ключ `General.hold` совпадает со схемой конфига |

## 4. Что сделано хорошо

- **Окно действует только на клавиши с двумя значениями.** Это и есть то,
  без чего ввод был бы невозможен: если бы окно ждало каждый символ, печатать
  было бы нельзя. Правило записано и в коде, и в документации крейта.
- **Клавиша без окна всегда тап.** У неё нет второго значения, и ждать
  нечего.
- **Граница окна задана точно.** 199 мс — тап, 200 мс — удержание. Тест
  называет это прямо: «первая удерживаемая миллисекунда».
- **Ноль окна — осмысленное значение.** «Удержание без ожидания»: специально
  выбранное поведение, а не случайность.
- **Настройки собираются в любом порядке и показываются по алфавиту.**
  `BTreeMap` даёт ровный порядок, а конфиг читается сверху вниз.
- **Повтор в настройках заменяет, а не плодит.** Одна клавиша в конфиге — одна
  в памяти.

## 5. Находки

| # | Серьёзность | Где | Что не так |
| --- | --- | --- | --- |
| 1 | важно | `src/lib.rs:1` | Заголовок крейта обещает «Клавиши как позиции, раскладки, модификаторы, составление, лидер, отмена» — из этого сделано только удержание. Код и документация крейта расходятся: читатель поверит, что половина слоя ввода готова |
| 2 | важно | `src/hold.rs:108` | Тип `Tap` не используется нигде и не выдаётся ни одной функцией. Он дублирует `Resolved` без варианта `Waiting` — два типа на одно и то же решение |
| 3 | важно | `src/hold.rs:117` | Вариант `Resolved::Waiting` никогда не выдаётся: `resolve` возвращает только `Tapped` и `Held`. Смысл варианта — «отпускания ещё не было, окно не истекло» — в функции не выражен: вызывающий сам обязан знать, что окно ещё живо, иначе он не спросит. Либо `resolve` должна уметь отвечать «ждём», либо вариант лишний |
| 4 | мелочь | `src/hold.rs:30` | Два почти одинаковых метода: `window_ms() -> u128` и `window_millis() -> u64`, плюс свободная функция `window_millis`. Три имени для одного и того же числа; различаются только типом, а `u64` достаточно везде |
| 5 | мелочь | `src/hold.rs:30` | `window_ms` отдаёт `u128` и обрезает `Duration` в миллисекунды: окно меньше миллисекунды становится нулём, а нулевое окно означает «всегда удержание». Тест фиксирует это как поведение |
| 6 | мелочь | крейт | Нет своего `defaults.rs` в форме `Default<T>`, как у `claxis-buffer`: ключ, значение и комментарий разъехались — ключ в комментарии (`General.hold`), значение в константе, комментарий для конфига в схеме конфига |
