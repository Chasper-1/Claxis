# Ревью: `claxis-config`

Дата ревью: 2026-11-12 (вторая версия).
Состояние крейта: 3250 строк, 67 тестов, все проходят.

## 1. Назначение и границы

Крейт — конфиг: набор файлов по одному на состояние, схема ключей, чтение,
генерация, точечная запись.

| Что есть | Что не входит в крейт |
| --- | --- |
| Схема: какие ключи бывают, их типы и значения по умолчанию | Что значит ключ: это дело редактора |
| Чтение файлов с разбором и списком проблем | Как выглядит интерфейс |
| Генерация файлов со всеми ключами и комментариями | Запись на диск: это `claxis-disk` |
| Точечная запись одного ключа с сохранением комментариев | Наблюдение за файлами |
| Раскладка на диске (`$XDG_CONFIG_HOME/claxis`) | — |

Зависимости: `claxis-text`, `claxis-i18n` (подписи и комментарии),
`claxis-disk` (запись), `claxis-input` (настройки ввода), `toml_edit`.

## 3. Публичный API

| Элемент | Оценка |
| --- | --- |
| `Config::{get, string_or_default, u16_or_default, u8_or_default, bool_or_default, table, has, unknown_keys}` | Уместны, но доступ по умолчанию молчит о неверном типе — находка 3 |
| `KEYS`, `TABLES`, `find`, `find_table`, `keys_of` | Уместны: один список — источник правды |
| `generate::{ensure_files, render, read_all, write_value}` | Уместны |
| `load::{parse, fold_inline_tables, line_of, value_matches}` | Уместны |
| `Issue`, `Problem`, `Loaded` | Уместны: проблема несёт файл, строку и ключ |

## 4. Что сделано хорошо

- **Один список ключей — источник правды.** Генератор берёт оттуда и значения,
  и комментарии; проверка сверяет с ним файл пользователя. Расхождение
  невозможно, потому что список один.
- **Загрузка никогда не падает целиком.** Ошибка в одной секции не должна
  отключать остальные: плохая секция отбрасывается, остальные работают, список
  проблем возвращается вместе с конфигом.
- **Проблема несёт файл, строку и ключ.** Это ровно то, что нужно, чтобы
  открыть конфиг и поставить курсор на место, которое надо исправить.
- **Неизвестный ключ — ошибка.** Молчаливый пропуск означал бы, что опечатку
  в настройке никто не заметит.
- **Плохая секция выключается целиком.** Остальные настройки из неё могут
  оказаться неверными из-за той же опечатки.
- **Правило проверки типов одно и на запись, и на чтение.** `value_matches`
  использует тот же `check`, что и разбор: иначе ключ можно было бы положить
  в конфиг в виде, который сам же разбор потом отвергнет.
- **Точечная запись сохраняет комментарий пользователя и порядок ключей.**
  Значение меняется, оформление остаётся.
- **Комментарии переводятся.** Ключом служит английская фраза, переводчик
  видит фразу, а не код.
- **Схема описывает и табличные настройки.** Имена ключей внутри таблицы —
  данные, их нельзя перечислить, поэтому для них отдельный тип `TableDef`.
- **Формат конфига — свой, и он рабочий.** Встроенные таблицы пишутся по
  строке на пару, а перед разбором сворачиваются в строку и обратно
  разворачиваются при записи. Это формат проекта; ревью его не оспаривает.

## 5. Находки

| # | Серьёзность | Где | Что не так |
| --- | --- | --- | --- |
| 1 | важно | `src/schema.rs:249` | Значения по умолчанию в схеме написаны литералами (`"8192"`, `"3"`, `"true"`, `"7d"`), а в крейтетах лежат константы (`claxis-buffer::DEFAULT_DEPTH`, `claxis-disk::KEEP`, `claxis-disk::PERSIST`, `claxis-save::DEFAULT_RETENTION`). Два места правды о значении по умолчанию: разъедутся, и ничто их не сверит |
| 2 | важно | `src/lib.rs:89` | Неверный тип значения молча заменяется значением по умолчанию: `u16_or_default` берёт `as_integer()`, и если ключ есть, но это строка, получается `None` — и тихо подставляется `8192`. Разбор конфига такой случай ловит и отбрасывает секцию, но сам API конфига на это не смотрит и ничего не говорит. Правило проекта: неизвестное из конфига — ошибка, а не дефолт |
| 3 | важно | `src/generate.rs` | 1283 строки — больше лимита в тысячу. Генератор, чтение всех файлов, точечная запись, сворачивание и разворачивание таблиц — это пять разных дел в одном файле |
| 4 | мелочь | `src/lib.rs:183` | `unknown_keys` обходит только секции первого уровня и их прямые ключи. Ключи внутри табличной настройки (`General.hold.alt`) попадут в список неизвестных: в схеме их нет, а таблица `General.hold` — есть. Сейчас функцией пользуются только тесты, но как только ею начнут пользоваться по назначению, пользователю посыплются ложные «неизвестные ключи» |
| 5 | мелочь | `src/load.rs:469` | `line_of` ищет секцию по строке вида `[General]`. Заголовок с комментарием (`[General] # моё`) не подходит, и номер строки для такой секции не найдётся — проблема при этом всё равно возникнет, просто без номера строки |
| 6 | мелочь | `src/lib.rs:77` | `string_or_default` при неверном типе тоже молча берёт значение по умолчанию — та же находка 2, но для строк |
| 7 | мелочь | `src/load.rs:99` | Сворачивание выносит комментарии из-под таблицы на отдельные строки после неё. Текст не теряется, но место меняется: человек написал комментарий внутри таблицы, а получит его под таблицей |
| 8 | мелочь | `src/schema.rs:229` | Схема описывает 12 ключей, а демо-конфиг (`demo-config/`) содержит заметно больше: мышь, статус-строку, автодополнение, раскладки. Это записано в `TODO.md` как отдельная задача, но разрыв будет расти, пока схема не догонит демо |

## 6. Нарушения правил из `AGENTS.md`

| Правило | Как в этом крейте |
| --- | --- |
| `unwrap`/`expect`/`allow`, имена с `_` | Не найдено в крейте (в тестах `expect` есть, это осознанно) |
| Файл больше 1000 строк | Нарушено: `generate.rs` — 1283 строки (находка 3) |
| Паника вместо ошибки | Паник нет: плохая секция отбрасывается, проблема возвращается списком |
| Ошибка доходит до пользователя текстом | Да: `Issue` несёт файл, строку, ключ и текст через каталог |
| Неизвестное из конфига — ошибка, не дефолт | Нарушено в доступах `Config` (находка 2); на уровне разбора соблюдено |
| Молчание только с комментарием | Соблюдено |
| Тест рядом с кодом | Да |
| Каталог у крейта с первого дня | Есть, `src/messages.rs` |
| Новые зависимости только при необходимости | `toml_edit` — разбор и запись с сохранением оформления, `claxis-i18n` — подписи, `claxis-input` — настройки ввода |
| `unsafe` | Не используется (в тестах `path.rs` — `set_var`, с комментарием `SAFETY`) |
| `std::fs` только в `config` и `disk` | Соблюдено: `read_all` и `open_for_edit` читают файлы напрямую, запись идёт через `claxis-disk` |

Нарушений три: файл больше тысячи строк, молчаливый дефолт при неверном типе,
дублирование значений по умолчанию.

## 7. Тесты

67 тестов, все проходят.

| Что покрыто | Чего не хватает |
| --- | --- |
| Генерация: файл без единой проблемы, таблицы собираются из файла, значения совпадают со схемой | — |
| Разбор: чистый файл, неизвестный ключ с номером строки, неверный тип, плохая секция отбрасывается, чужая секция, один плохой файл не ломает другой, сломанный синтаксис | — |
| Сворачивание таблиц: многострочная таблица, скобки в строке, комментарии, вложенные таблицы | Массив с встроенной таблицей (`[{a = 1}]`) — не проверено |
| Точечная запись: комментарий сохранён, значение заменено, чужая секция не тронута | — |
| Схема: имена файлов, общие настройки отдельно от состояний, поиск по пути | — |
| Пути: XDG, пустая переменная, папки тем и переводов | — |
| Доступ к значениям: чтение из нужного файла, откат к значению по умолчанию, файлы не протекают друг в друга | Неверный тип значения (находка 2) — не проверяется |
| Неизвестные ключи: найден и не найден | Ключ внутри табличной настройки (находка 4) — не проверяется |

Тесты крейте сильные: генератор проверяется тем, что его собственный вывод
разбирается без единой проблемы, а значения сверяются со схемой. Пробелы —
ровно там, где находки: неверный тип в доступах и ключи внутри таблиц.

## 8. Долг и предложения

По порядку:

1. **Ссылаться на константы крейтов из схемы** (находка 1): одна правка,
   конец дублированию.
2. **Не подставлять дефолт при неверном типе** (находки 2 и 6): доступ должен
   различать «ключа нет» (тогда дефолт) и «ключ есть, но не того типа» (тогда
   ошибка).
3. **Разнести `generate.rs`** (находка 3) на генерацию, чтение и запись.
4. **Починить `unknown_keys`** (находка 4) до того, как функцией начнут
   пользоваться.

Правки 1 и 2 маленькие и снимают два класса расхождений.
