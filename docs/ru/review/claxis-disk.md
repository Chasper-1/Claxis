# Ревью: `claxis-disk`

Дата ревью: 2026-11-12 (вторая версия).
Состояние крейта: 3065 строк в исходниках, 96 тестов, все проходят.

## 1. Назначение и границы

Крейт — единственный в проекте, кто трогает диск.

| Что есть | Что не входит в крейт |
| --- | --- |
| Запись файлов атомарно: временный файл и переименование | Решение, что и когда записывать |
| Чтение, размер файла, список файлов | Формат файлов редактора |
| Наблюдение за каталогами через `notify` | Решение, чьи это файлы |
| Хранилище снапшотов в SQLite, кольцо, якорь «база ↔ диск» | Формат истории: это `claxis-buffer` |
| Контрольная сумма (FNV-1a) и хеш содержимого (XXH3-128) | Проверка «менялся ли файл»: это `claxis-save` |

Зависимости: `claxis-text`, `xxhash-rust`, `rusqlite` (bundled), `notify`.
Границы соблюдены: крейт не решает и не проверяет, он пишет правильно и
сообщает об отказе.

## 4. Что сделано хорошо

- **Запись атомарна и не оставляет мусора.** Временный файл рядом с целью
  (переименование атомарно только внутри одного каталога), `sync_all` перед
  переименованием, удаление временного файла при любой ошибке. Тест
  `no_temporary_file_is_left_behind` проверяет, что рядом с конфигом не
  остаётся ничего лишнего.
- **Ошибка всегда несёт путь.** `io` и `write_io` различают чтение и запись,
  и обе приносят путь: ошибка без пути — это «что-то сломалось».
- **Снапшоты проверяются суммой.** `checked` отказывается отдавать текст, если
  сумма не сходится, и различает два случая: запись виновата (переписать) и
  переписали снаружи (сказать человеку).
- **Сумма покрывает и текст, и историю, и их порядок.** `of_pair` включает
  длину первого куска, поэтому `ab`+`c` и `a`+`bc` не совпадают.
- **Якорь «база ↔ диск» в базе.** Размер и XXH3-128: две ступени, сначала
  дешёвая. Якорь переживает перезапуск, и это проверяется отдельно.
- **Миграции идут на месте и не теряют базу.** Столбцы добавляются через
  `ALTER`, уже существующий столбец — не ошибка. База пользователя не
  пересоздаётся из-за новой версии.
- **Наблюдение не молчит.** Ошибки системы и «слепые зоны» собираются и
  отдаются вызывающему: молчащее наблюдение хуже явного отказа — правка
  перестаёт применяться, а выглядит всё так же.
- **События устоявшиеся отдаются, свежие ждут.** Пауза в 120 мс: файл мог быть
  дописан прямо сейчас.
- **Отравленный ящик не теряет ошибку.** И в `changed()`, и в `report()`
  данные забираются и при отравленном мьютексе.
- **Сумма считается по кускам.** Большой файл не держится в памяти целиком.

## 5. Находки

| # | Серьёзность | Где | Что не так |
| --- | --- | --- | --- |
| 1 | важно | `src/file.rs:135` | Имя временного файла — только имя цели и номер процесса: `config.toml.tmp1234`. Две записи одного и того же пути из одного процесса (две нити или два вызова подряд) получат одно и то же имя. Вторая перезапишет временный файл первой, а переименование унесёт не тот текст |
| 2 | важно | `src/defaults.rs`, `claxis-config/src/schema.rs` | Значение по умолчанию задано дважды: `KEEP = 3` и `PERSIST = true` в диске, и `"3"` / `"true"` в схеме конфига. Плюс в диске настройки описаны как «Ключ: `keep`», а настоящий путь — `General.snapshots_keep`. Два места правды о значении по умолчании разъедутся, и ничто их не сверит |
| 3 | важно | `src/snapshots.rs` | 1409 строк — больше лимита в тысячу. В `TODO.md` помечено «пока не трогаем», но при следующем добавлении схемы базы файл перестанет помещаться в лимит |
| 4 | мелочь | `src/watch.rs:63` | `#[expect(dead_code, reason = "…")]` — подавление линта, то же, что запрещённый `#[allow]`, только в новой форме. Правило в `AGENTS.md` написано про `allow`, и `expect` подпадает под тот же смысл. Поле действительно держит подписку, но заглушить можно иначе |
| 5 | мелочь | `src/checksum.rs`, `src/error.rs` | Мёртвый публичный API: `checksum::of`, `checksum::of_reader`, `checksum::of_file` никем не вызываются (нужен только `of_pair`), а вариант `Error::WatchFailed` не используется нигде: наблюдение отдаёт ошибки строками, а не этим вариантом |
| 6 | мелочь | `src/watch.rs:205` | `touch` ищет путь линейным перебором: каждое событие — `O(n)` по списку ожидающих. При тысяче файлов под наблюдением это заметно |
| 7 | мелочь | `src/watch.rs:26` | Пауза в 120 мс — константа в коде, не настройка. Плюс у наблюдения нет таймера: `changed()` вызывается только когда есть что спросить, а тикать без событий оно не умеет |
| 8 | мелочь | `src/file.rs:65` | `list_files` обходит `metadata` для каждой записи и падает на битой символической ссылке: один сломанный симлинк роняет весь список файлов |
| 9 | мелочь | `src/temp.rs:34` | `expect("временный каталог создаётся")` — паника в коде, а не только в тестах: модуль собирается и под тестами других крейтов (`test-support`) |
| 10 | мелочь | `src/snapshots.rs:234` | `take` при чтении снапшота без суммы дописывает её в базу: чтение меняет базу. Для одного процесса безвредно, но при двух подключениях это запись из пути чтения |
| 11 | мелочь | `src/hash.rs` | Две разные суммы в одном крейте: XXH3-128 для якоря и FNV-1a для снапшотов. Обе задокументированы и обе на своём месте, но в коде легко перепутать, какая где |

## 6. Нарушения правил из `AGENTS.md`

| Правило | Как в этом крейте |
| --- | --- |
| `unwrap`/`expect`/`allow`, имена с `_` | `expect` в `temp.rs` (находка 9), `#[expect]` в `watch.rs` (находка 4) |
| Файл больше 1000 строк | Нарушено: `snapshots.rs` — 1409 строк (находка 3) |
| Паника вместо ошибки | Только в тестовой утилите |
| Ошибка доходит до пользователя текстом | Да: у каждого варианта ошибки есть текст через каталог, примеры в `samples()` |
| Молчание только с комментарием | Соблюдено: наблюдение отдаёт ошибки, запись чистит мусор |
| Тест рядом с кодом | Да |
| Каталог у крейта с первого дня | Есть, `src/messages.rs` |
| Новые зависимости только при необходимости | `rusqlite` — для кеша снапшотов, `notify` — для наблюдения, `xxhash-rust` — для якоря. Каждая нужна |
| `unsafe` | Не используется (в тестах `path.rs` — `set_var` в Rust 2024, с комментарием `SAFETY`) |
| `std::fs` только здесь | Соблюдено: прямой `std::fs` есть только в `claxis-disk` (проверяется сторожевым тестом) |
| Крейты напрямую | Только `claxis-text`, лист |

Нарушений четыре: `expect`, `#[expect]`, файл больше тысячи строк, дублирование
значений по умолчанию между крейтом и схемой конфига.

## 8. Долг и предложения

По порядку:

1. **Сделать временное имя уникальным** (находка 1): счётчик в процессе или
   случайный суффикс. Правка в одну строку, риск — порча текста при двух
   параллельных записях одного пути.
2. **Убрать дублирование значений по умолчанию** (находка 2): либо диск берёт
   значение из схемы конфига, либо схема ссылается на константы диска. Сейчас
   оба места правды, и ничто их не сверяет.
3. **Решить, что делать с `#[expect]`** (находка 4): правило в `AGENTS.md`
   запрещает `#[allow]`, и `expect` — тот же приём. Либо правило уточняется,
   либо подавление убирается.
4. **Почистить мёртвый API** (находка 5): `checksum::of` и `Error::WatchFailed`.
5. **Разнести `snapshots.rs`** (находка 3), когда владелец решит трогать.

Правки 1 и 2 — маленькие и снимают риск порчи текста и разъезда настроек.
